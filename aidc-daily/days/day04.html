哪项是 Active，
就看下面对应编号的格子

Idle 为 Active 很正常，
只是卡上没活干

SW 开头：驱动主动控频，温和
HW 开头：硬件保护，频率直接砍半以上

① 太热了
SW Thermal Slowdown
确认
nvidia-smi -q -d TEMPERATURE

当前温度逼近 GPU Slowdown Temp，显存温度也要看

常见

液冷流量不足、进水温度偏高、导热不良、风扇故障

处理

查 CDU 流量、供回水温差和冷板；风冷查风扇与气流

② 功耗到顶
SW Power Cap
确认
nvidia-smi -q -d POWER

功耗读数贴着当前功耗上限

常见

满载时的正常现象；也可能是上限被人用 -pl 调低了

处理

满载出现可以接受；上限低于默认值就恢复

③ 硬件保护
HW SlowdownHW ThermalHW Power Brake
确认
nvidia-smi -q -d PERFORMANCE

HW 开头的任一项为 Active，同时去 BMC 查电源事件

触发

过温、外部 Power Brake 信号、瞬时功耗过高

影响

频率直接砍半以上，整个训练跟着变慢

处理

查 PSU、供电母线和 BMC 日志；反复出现就隔离节点

④ 被人锁了
Applications Clocks Setting
确认
nvidia-smi -q -d CLOCK

看当前频率是否被固定在偏低值

常见

调试时 -lgc 锁频没恢复，或旧的 -ac 设置残留

处理
nvidia-smi -rgc

恢复默认频率（-ac / -rac 已弃用）
