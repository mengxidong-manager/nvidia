一条链：从「认出 GPU」到「出监控」
组件Pod（-n gpu-operator）干什么坏了的样子
0NFD…node-feature-discovery-…

扫 PCI，打 pci-10de.present=true，Operator 据此认出 GPU 节点

没这个标签，后面一个都不部署

1Drivernvidia-driver-daemonset

用容器给宿主机装 NVIDIA 驱动

CrashLoop：内核版本不匹配

2Container Toolkitnvidia-container-toolkit-daemonset

给 containerd 注册 nvidia 运行时

Pod 里 NVML 初始化失败

3Device Pluginnvidia-device-plugin-daemonset

向 kubelet 上报 nvidia.com/gpu 资源

节点没 GPU 可分，Pod Pending

4GFDgpu-feature-discovery

打 gpu.product / gpu.count / gpu.memory 标签

nodeSelector 选不到节点

5DCGM Exporternvidia-dcgm-exporter

:9400 暴露 DCGM_FI_* 指标

Grafana 没数据

链式依赖：下游 Pod 的 init 容器要等上游写好 /run/nvidia/validations/ 下的 ready 文件，一层没起来，后面全卡在 Init

另外两位
Validatornvidia-operator-validator

按 driver → toolkit → cuda → plugin 逐层验收；nvidia-cuda-validator 显示 Completed 才算过

MIG Managernvidia-mig-manager

按节点标签 nvidia.com/mig.config 切 MIG，默认策略 single

默认不装，按需打开
GDS（nvidia-fs）GDRCopyvGPU ManagerKata / 机密计算独立 DCGMDRA（实验）

独立 DCGM 默认关：Exporter 里自带 hostengine。DRA 走另一套 CR，和 ClusterPolicy 不能同时存在

安装与排查
装 helm repo add nvidia https://helm.ngc.nvidia.com/nvidia helm install --wait --generate-name -n gpu-operator --create-namespace nvidia/gpu-operator

已预装驱动加 --set driver.enabled=false；Toolkit 也装了再加 toolkit.enabled=false

查 kubectl get pods -n gpu-operator kubectl get node -L nvidia.com/gpu.product -L nvidia.com/gpu.count kubectl logs -n gpu-operator -l app=nvidia-driver-daemonset

从上往下找第一个不是 Running 的 Pod，它就是根因
