Device Plugin 经 /var/lib/kubelet/device-plugins/kubelet.sock 向 kubelet 注册，ListAndWatch 持续上报卡数和健康状态 → 节点 Allocatable 里出现 nvidia.com/gpu: 8

一个 GPU Pod 的七跳
1API Server

Pod 在 limits 里写 nvidia.com/gpu: 1

没写 limits，容器里看不到卡
2Scheduler

只按整数数节点上的空卡，选节点；不知道是哪一张

Pending：Insufficient nvidia.com/gpu
3kubelet

建容器前调 Device Plugin 的 Allocate，这时才定下用哪张卡

Plugin 没起来：UnexpectedAdmissionError
4Device Plugin

返回选中的卡：默认给 CDI 设备名；关了 CDI 就给环境变量 NVIDIA_VISIBLE_DEVICES=GPU-uuid

给错卡 / 给空：容器里卡数不对
5containerd

生成 OCI spec，交给 nvidia-container-runtime

没配 nvidia runtime：容器里没 GPU
6NVIDIA Runtime

改 OCI spec：挂入 /dev/nvidia*、libcuda.so、nvidia-smi，再交给 runc

Failed to initialize NVML
7CUDA 程序

镜像里的 CUDA runtime → 宿主机的 libcuda → 内核驱动 → GPU

CUDA driver version is insufficient
注入方式：新 vs 旧
CDI（GPU Operator 默认）

Toolkit 把「这张卡要挂哪些设备和库」写成 spec，放在 /var/run/cdi；Device Plugin 只报设备名，按 spec 注入

环境变量 + prestart hook（旧）

Runtime 读 NVIDIA_VISIBLE_DEVICES，用 prestart hook 调 nvidia-container-cli 挂载

CUDA 官方镜像默认 NVIDIA_VISIBLE_DEVICES=all：旧方式下，没申请 GPU 的 Pod 也可能看到全部卡

谁带什么
镜像带

CUDA runtime（libcudart）

cuDNN、NCCL、框架

宿主机带

内核驱动模块

libcuda.so、libnvidia-ml.so

nvidia-smi

驱动只能来自宿主机，由 Runtime 挂进容器。镜像的 CUDA 版本不能比驱动支持的新，否则报 insufficient

容器里跑 nvidia-smi，右上角的 CUDA Version 是宿主机驱动支持的上限，不是镜像里的版本
