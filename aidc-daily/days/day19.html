按级别分三档
P0 立即处理
changes(DCGM_FI_DEV_XID_ERRORS[5m]) > 0

出现新 XID；再按值分级：48 / 79 / 95 直接隔离

DCGM_FI_DEV_ROW_REMAP_FAILURE == 1

行重映射失败，备用行耗尽 → 换卡

count by (Hostname)(DCGM_FI_DEV_GPU_TEMP) < 8

节点上报的卡少了 → 掉卡

P1 当天处理
increase(DCGM_FI_DEV_UNCORRECTABLE_REMAPPED_ROWS[1h]) > 0

有新的不可纠正行被重映射 → 排期重启完成 remap

DCGM_FI_DEV_GPU_TEMP > 阈值，for 5m

阈值按型号定：低于 Slowdown Temp 留余量

P2 盯趋势
increase(DCGM_FI_DEV_PCIE_REPLAY_COUNTER[1h]) > 0

PCIe 重传在涨 → 查插槽、Riser、线缆

avg_over_time(DCGM_FI_DEV_GPU_UTIL[1h]) < 10

卡分出去却长期空闲 → 回收资源

四个坑：规则写了却不响
① ECC 计数默认不采

GPU Operator 用 dcp-metrics-included.csv，ECC、NVLink 错误、限频时长都被注释掉。基于 ECC_DBE_VOL_TOTAL 的告警永远不会响

② XID 是「最后一次的值」

DCGM_FI_DEV_XID_ERRORS 是 gauge，不是次数。写 > 0 会一直响，要用 changes() 抓新的

③ 掉卡时指标直接消失

卡掉了就没有数据，温度、利用率阈值都不会触发。要单独告警「卡数变少」

④ 利用率高 ≠ 算力用满

GPU_UTIL 只看有没有 kernel 在跑；看真实负载用 PROF_PIPE_TENSOR_ACTIVE

把缺的指标打开
  1. 拷一份 dcp-metrics-included.csv，去掉 ECC、NVLink 错误、限频那几行的 #
  2. 做成 ConfigMap 放进 gpu-operator 命名空间
  3. ClusterPolicy 里 dcgmExporter.config.name 指向它
