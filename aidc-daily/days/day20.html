超限后会发生什么
实际数据（in use）
碎片：删掉的空间，文件没缩
剩余
配额：默认 2GB
DB 文件超过配额→全集群 NOSPACE 告警→只能读和删→K8s 写不进：Pod 建不了、ConfigMap 改不了
etcdserver: mvcc: database space exceeded

compact 只删旧版本历史，空出来的地方留在文件里给 etcd 复用

defrag 才把文件真正缩小、还给磁盘；期间这个成员读写都会阻塞

抢救五步
1
etcdctl alarm list

看到 alarm:NOSPACE 就是超限了

2
etcdctl compact $rev

$rev 取 endpoint status 里的当前 revision

3
etcdctl defrag --endpoints=<单个成员>

一次一台，Leader 放最后

4
etcdctl alarm disarm

空间腾出来以后再解除

5
etcdctl endpoint status -w table

DB SIZE 降下来，试写一个 key

先找是谁撑大的
etcdctl get /registry --prefix --keys-only \
 | awk -F/ 'NF>2{print $3}' \
 | sort | uniq -c | sort -rn | head

按资源类型数 key，排前面的就是嫌疑人

Event 堆积海量 Job / Pod大 ConfigMap、SecretCRD 对象失控

Event 默认只留 1 小时（--event-ttl）：Event 还能堆满，说明有组件在疯狂刷事件，先找它

kube-apiserver 默认每 5 分钟压缩一次历史，K8s 集群里的 etcd 撑满，多半是真数据多了或碎片没整理

预防：告警按比例，不按绝对值
容量告警etcd_mvcc_db_total_size_in_bytes
/ etcd_server_quota_backend_bytes
> 0.8
碎片告警1 - etcd_mvcc_db_total_size_in_use_in_bytes
/ etcd_mvcc_db_total_size_in_bytes
> 0.5
调配额

默认 2GB，官方建议上限 8GB，再大影响性能；所有成员一起改，逐台重启
