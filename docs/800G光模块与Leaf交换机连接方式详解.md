# 800G/400G 光模块与 Leaf 交换机连接方式详解

> 基于实机模块铭牌核实：服务器侧 800G OSFP DR8/RHS 拆分为 2×400G，分别连接 H3C S9827-128DH 等 Leaf 交换机的完整链路分析
>
> 撰写人：孟希東

---

## 一、MPO 连接器基础

MPO（Multi-fiber Push-On）是一次性可承载多根光纤的连接器，800G 光模块的光口普遍采用 **MPO-12** 或 **MPO-16** 规格：

| 连接器 | 光纤数 | 典型用途 |
|--------|--------|----------|
| MPO-12/APC | 12 芯（8 芯用于传输，斜面抛光减少反射） | DR8 单模模块 |
| MPO-16 | 16 芯（8 发 8 收） | SR8 多模模块 |

> `/APC`（Angled Physical Contact）是斜面抛光，专用于单模光纤长距传输，插错方向或误用 UPC 平面接头会导致高误码率——这是排障时最容易忽视的细节。

## 二、800G 光模块的通道拆分原理

800G 一个物理端口内部由 **8 条 100G-PAM4 通道**组成，这是所有拆分方式的基础：

```
一个 800G OSFP 端口 = 8 × 100G-PAM4 lane
```

同一个物理模块可以配置成不同的拆分（breakout）模式：

| 拆分模式 | 通道分配 | 典型场景 |
|----------|----------|----------|
| **1×800G 直连** | 8 lane 全部给一个端点 | 交换机对交换机高速互联 |
| **2×400G** | lane 0-3 给第一路，lane 4-7 给第二路 | 一个交换机/网卡端口连接两台设备（**本文档实机场景**） |
| **4×200G** | 每路 2 lane | 连接 200G 网卡 |
| **8×100G** | 每路 1 lane | 交换机对多台低速设备扇出 |

两颗模块 SN 前缀均为 `MF26`，判断为**同一厂商同批次采购**的产品线，型号命名规则一致，便于备件管理和批次故障排查（若某 SN 段出现光衰异常，可按前缀快速圈定排查范围）。

### 3.3 规格字段拆解

| 字段 | 含义 |
|------|------|
| `800Gbps` / `400Gbps` | 总带宽 |
| `500m` | 最大传输距离（单模光纤） |
| `SM` | Single Mode，单模光纤 |
| `DR8` | 8 通道 DR（Data center Reach）规格，即 8×100G-PAM4，服务器/网卡侧常用 |
| `DR4` | 4 通道 DR 规格，即 4×100G-PAM4，交换机侧 400G 端口常用 |
| `OSFP` / `QSFP` | 模块封装形态，OSFP 用于 800G，QSFP(-DD) 用于 400G |
| `RHS` | Riding Heat Sink，骑乘式散热片（详见下节） |

## 四、关键细节：RHS vs IHS 散热外壳

这是实机排查中最容易忽视但影响装配的细节：

| 外壳类型 | 外观 | 典型安装位置 |
|----------|------|--------------|
| **IHS**（Integrated Heat Sink，finned-top 鳍片式） | 表面有散热鳍片 | 交换机侧（Quantum-2/Spectrum-4 cage 自带风道，高功耗模块仍需鳍片辅助散热） |
| **RHS**（Riding Heat Sink，flat-top 平顶式） | 表面平整，无鳍片 | 服务器/网卡侧（如 ConnectX-7/8 的 OSFP 端口，靠网卡侧散热片"骑乘"在模块上方） |

> 同一速率的模块，交换机侧和服务器/网卡侧的散热片形态不同，装错位置会导致散热不良甚至物理装配失败。本次实机核实的 RTXM600-2401 标注为 RHS，确认装在服务器侧的 ConnectX SuperNIC 端口。

## 五、常见 800G 模块型号速查

| 模块型号 | 光口规格 | 传输距离 | 典型应用 |
|----------|----------|----------|----------|
| **OSFP SR8** | MPO-16，多模 | 短距（机柜内/相邻机柜） | 服务器到 leaf 的主流选择，支持拆分为 2×400G |
| **OSFP DR8** | MPO-12/APC，单模 | 500m 内 | 跨机柜/跨行连接，本文档实机场景 |
| **2×DR4 双工模块**（如 NVIDIA MMS4X00-NS） | 两个独立 MPO-12/APC | 100m（经两个配线架） | 交换机对交换机互联主力型号，一个模块物理上是两个独立 400G 链路 |
| **2×FR4 / 2×LR4** | 单模 | 2km / 10km | 跨数据中心互联（DCI） |

## 六、实机完整拓扑

```
服务器 ConnectX-8 网卡
    │
    ▼
800G OSFP DR8 模块（RTXM600-2401，RHS，服务器侧）
    │  MPO-12/APC 内部 8 条 100G-PAM4 通道
    │
    ▼
MPO 分支光缆（1 分 2）
    │
    ├──── lane 0-3 ────▶ 400G QSFP DR4 模块 ──▶ Leaf 交换机 A（如 roce-leaf-31）
    │
    └──── lane 4-7 ────▶ 400G QSFP DR4 模块 ──▶ Leaf 交换机 B（如 roce-leaf-32）
```

结合此前在同一机架采集的标签 `osadrt-s110-i2u18-roce-leaf-31-55` 和 `osadrt-s110-i2u10-roce-leaf-32-55`，物理层模块型号与端口速率完全吻合：**一个 800G DR8 口在服务器侧，物理拆分成两路独立的 400G 链路，分别接到两台不同的 leaf 交换机**。

## 七、更大范围的多路径拓扑（Rail-optimized）

实机同一台服务器同时连接到十余个不同 leaf 编号（`leaf-3/7/8/9/11/17/18/20/24/25/27...`），这是标准的 **Rail-optimized（导轨优化）拓扑**：8 颗 GPU 各自的网卡不接到同一台 leaf，而是分散接到不同 leaf。

```
Leaf 层（Top-of-Rack，如 Spectrum-4 SN5600 / H3C S9827-128DH）
    │  接受所有互联类型（IHS/RHS OSFP 均兼容）
    │  每个 800G 口可拆 2×400G / 4×200G / 8×100G
    ▼
Spine 层（如 Quantum-X800 Q3400-RA）
    │  leaf-to-spine 用 DAC/AEC（近距离）或光模块（远距离）
```

### 设计意义

| 目的 | 说明 |
|------|------|
| **双上联冗余** | 一张网卡对应两条独立物理路径，任一台 leaf 交换机故障，只丢失一半带宽而非完全断链 |
| **降低 AllReduce 跳数** | 同一 "rail" 编号的 GPU（如所有节点的 GPU0）走同一组 leaf，减少跨 leaf 跳数和通信延迟 |
| **端口经济性** | 交换机侧用更主流、更便宜的 400G 端口，无需下联设备全部支持 800G |
| **代际过渡兼容** | 服务器网卡是新一代 800G 接口，leaf 交换机可能仍是 400G 一代（如 Spectrum-3 SN4000 系列），拆分方案让新老代际设备共存组网，是集群升级期的常见过渡方案 |

## 八、Leaf 交换机实机核实：H3C S9827-128DH

本集群的 RoCE Leaf 交换机之一经实机铭牌核实为国产设备：

### 8.1 设备铭牌

| 字段 | 值 |
|------|-----|
| 厂商 | H3C（新华三） |
| 型号 | Densivelo **S9827-128DH** |
| S/N | 210235A5NL5264P000SD |
| RS S/N | RS81-2000-009E |

### 8.2 型号规格

| 参数 | 规格 |
|------|------|
| 端口密度 | 最多 128 × 400G QSFP112 端口（可降配为 64×800G） |
| 交换容量 | 51.2 Tbps |
| 关键技术 | LPO（Linear Pluggable Optics）线性直驱光模块技术，AI ECN、动态负载均衡 |
| 拆分能力 | 支持 800G 拆 2×400G、拆 4×200G，或降速到 400G |
| 协议支持 | 原生支持 RoCEv2，基于 PFC（优先级流控）+ ETS 实现无损网络 |
| 可观测性 | 支持通过 ERSPAN、gRPC 将实时资源信息和 RoCEv2 统计告警上报给运维平台 |
| 定位 | AIGC/智算场景专用 Leaf/Spine 交换机 |

### 8.3 实机端口速率确认

现场核实该交换机端口所插模块**标注为 400G**，即工作在原生 400G QSFP112 直插模式，未做拆分降速。这与服务器侧 800G DR8 模块拆分出的每一路 400G 完全对等，链路两端速率一致，是最简洁、最不易出问题的连接方式——不涉及交换机侧二次拆分，链路层配置也更简单：

```
服务器 800G OSFP DR8（拆 2×400G）
    │
    ├──▶ 400G QSFP DR4 模块 ──▶ H3C S9827-128DH 端口（原生 400G 直插）
    └──▶ 400G QSFP DR4 模块 ──▶ 另一台 Leaf 交换机（原生 400G 直插）
```

### 8.4 布线与理线细节

- 光纤先接入绿色 LC/MPO 适配器面板（配线架过渡），再引出黄色跳线连接服务器——好处是交换机端口本身不直接承受外部拉力，跳线损坏时只需在配线架侧维修，不影响交换机端口本体
- 标签体系延续 `A-XXX// s110-<机柜>-u15-roce-<leaf编号>` 格式，同一台交换机上的标签会同时出现指向不同 leaf/spine 编号的线缆，因为该交换机既是某些服务器的目标 leaf，也可能承载其他方向的跳线过渡

### 8.5 H3C 交换机侧故障排查

| 检查项 | 命令（H3C Comware/VRP 系统） |
|--------|-------------------------------|
| 端口状态 | `display interface brief` |
| RoCEv2/PFC 统计 | `display qos pfc statistics interface <口>` |
| 光模块状态 | `display transceiver interface <口>` |
| 光功率诊断 | `display transceiver diagnosis interface <口>` |
| 遥测配置确认 | 确认 ERSPAN/gRPC 已配置，供 AIOps 平台提前预警拥塞和丢包 |

> ⚠️ **LPO 模块特别提醒**：LPO（线性直驱）模块内部没有独立的 DSP 信号重整芯片，信号质量更依赖交换机 SerDes 和对端网卡的信号完整性，比传统 DSP 模块对线缆质量、走线弯曲半径、连接器清洁度更敏感——出现误码时应优先排查物理层清洁度和走线，而非默认怀疑模块本身故障。

## 九、实操验证流程

```bash
# 1. 确认模块被识别，查看模块信息
mlxlink -d /dev/mst/mt4129_pciconf0 -m
# 关注：Module ID / Cable Type / Vendor / 是否报错

# 2. 检查光功率（发送/接收）
mlxlink -d /dev/mst/mt4129_pciconf0 --show_module
# 正常范围通常在 -1 到 -7 dBm 之间，过低说明衰减异常（脏污/弯折/连接器损耗）

# 3. 确认链路速率和拆分模式生效
ethtool <接口名> | grep Speed
# 拆分模式下应显示对应的 400G，而非全速 800G

# 4. 检查链路层错误
ethtool -S <接口名> | grep -i -E "error|crc|symbol"

# 5. 确认对端 leaf 交换机端口状态一致
# 登录 Cumulus Linux 或 NVIDIA OS
nv show interface <port> --view=phy
```

## 十、故障排查速查表（模块层面）

| 现象 | 原因 | 处理 |
|------|------|------|
| 链路一直 Down/Flapping | MPO 极性接反（正反插反） | 检查极性标签，重新插拔确认方向 |
| 误码率高（High BER） | 光纤污染、模块老化、分支光缆故障 | 用光纤清洁笔清洁端面，必要时更换分支光缆 |
| 速率协商错误（显示 800G 而非预期的 2×400G） | 拆分模式配置与线缆类型不匹配 | 确认端口 breakout 模式设置与物理线缆规格一致 |
| lane 顺序错位（间歇性丢包，非完全不通） | DR8 拆 2×DR4 时物理通道对应关系与走线记录不一致 | 核对分支光缆的 lane 0-3/4-7 走线标签，重新梳理对应关系 |
| 某条 rail 链路异常但其他正常 | 单条 leaf 故障，不影响整机 | 对照标签定位具体 leaf 编号，隔离处理，多路径冗余保证训练任务不受影响 |
| 光功率过低 | MPO 连接器未插到位、光纤弯曲半径过小 | 重新插拔确认"咔嗒"声，检查光纤走线无过度弯折 |
| 模块装配困难/散热异常 | RHS/IHS 外壳类型与安装位置不匹配 | 确认服务器侧用 RHS、交换机侧用 IHS，勿混装 |

## 十一、备件与标签管理建议

- **模块型号+SN 记录**：建议在现有的机房/机柜/U位/leaf 编号标签体系基础上，补充光模块型号和 SN 记录，做到端到端可追溯
- **主备同型号存放**：备件库房按同规格模块存放（如实机场景中标记 "New" 的 400G DR4 备件），故障时可直接替换，无需重新确认兼容性
- **批次追溯**：同批次采购的模块 SN 前缀一致（如本文档 `MF26` 前缀），一旦出现批次性光衰或故障问题，可按 SN 段快速圈定受影响设备范围
