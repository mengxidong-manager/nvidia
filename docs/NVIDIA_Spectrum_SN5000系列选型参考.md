## 1. 系列定位

SN5000 是 NVIDIA 第五代以太网交换机，由 **Spectrum-4 ASIC** 驱动，端口速率覆盖 10G–800Gb/s。定位为数据中心 leaf / spine / super-spine 通用平台，也是 **Spectrum-X** 平台的核心交换组件。

Spectrum-X ＝ Spectrum-4 交换机 + BlueField-3 SuperNIC，是首个专为 AI 设计的以太网架构，官方标称相比传统以太网有 **1.6 倍** 的生成式 AI 网络性能提升。

> ⚠️ **重要**：这个 1.6 倍来自“NVIDIA 交换机 + NVIDIA 网卡”的端到端协同。若交换机换用其他厂商，Spectrum-X 作为整体方案不成立，该数据不可直接套用。

## 2. 两款型号规格对比

| 项目 | **SN5600** | **SN5400** |
|------|-----------|-----------|
| 形态 | 2U | 2U |
| 连接器 | 64× OSFP 800GbE + 1× SFP28 | 64× QSFP-DD 400GbE + 2× SFP28 |
| **交换容量** | **51.2 Tb/s** | **25.6 Tb/s** |
| 线速转发 | 33.3 Bpps | 33.3 Bpps |
| SerDes | 8× 100G PAM4 | 8× 50G PAM4 |
| 最大 800GbE | 64 | — |
| 最大 400GbE | 128 | 64 |
| 最大 200GbE | 256 | 128 |
| 最大 100GbE | 256 | 256 |
| 报文缓冲 | 160 MB（全共享） | 160 MB（全共享） |
| 转发表项 | 512,000（动态共享） | 512,000 |
| CPU / 内存 / SSD | 六核 x86 / 32G / 160GB | 同左 |
| 电源 | 2（1+1 冗余） | 2（1+1 冗余） |
| 风扇 | 4（N+1 冗余） | 4（N+1 冗余） |
| 风道 | 后向 | 后向、前向 |
| 电源输入 | 50–60Hz，208–264Vac | 同左 |
| **工作温度** | **0–35 ºC** | **0–40 ºC** |
| 尺寸（H×W×D） | 86.2 × 438 × 720 mm | 同左 |

**端口拆分能力**：SN5600 的 64 个 800G 口可拆为 128× 400G 或 256× 200G；SN5400 的 64 个 400G 口可拆为 128× 200G 或 256× 100G。这是 leaf 侧接入密度的关键。

## 3. 关键能力

### 3.1 性能

- 全共享单体式报文缓冲（160MB），跨所有端口，支持全端口直通而不牺牲规模
- 稳定的低 cut-through 时延
- **RoCE 加速**，并针对以太网 AI 云服务器提供扩展
- 512,000 条转发表项，可在 ACL、LPM 路由、主机路由、MAC、ECMP、隧道之间动态共享

### 3.2 高可用

| 能力 | 说明 |
|------|------|
| 电源 / 风扇 | 1+1 电源、N+1 风扇，均热插拔，颜色区分 |
| **ECMP** | **256 路**负载均衡 |
| MLAG | 多机箱链路聚合，active/active 二层多路径 |
| EVPN | 多归属 |
| ISSU | 硬件辅助在线软件升级 |

### 3.3 可视化（运维价值高）

- **What Just Happened（WJH）** —— 事件触发式的细粒度故障信息，显著缩短定位时间
- 硬件加速直方图（NetQ 驱动），**亚微秒粒度**跟踪队列深度 —— 排查 RoCE 拥塞极有用
- 带内网络遥测（INT）+ 流式遥测
- 512,000 个片上流计数器

### 3.4 安全

从 BIOS 到 NOS 全链路由内置硬件信任根认证，未经 NVIDIA 签名的组件或镜像被自动阻止运行。支持最高 12.8Tb/s MACsec / VXLANsec 加密。

## 4. 软件生态

| 方案 | 特点 | 适用 |
|------|------|------|
| **Cumulus Linux** | NVIDIA 自研开放 NOS，自动化与定制能力强 | 追求成熟商业支持 |
| **SONiC** | 完全开源、硬件无关、容器化，避免厂商锁定 | 大规模自运维团队 |
| **Linux Switch** | 基于 switchdev，可装任意标准 Linux 发行版 | 深度定制场景 |
| **NVIDIA Air** | 数字孪生仿真平台，含每台交换机与线缆的逻辑实例 | 变更前验证，官方称部署提速最多 95% |
| **NVIDIA NetQ** | 实时可视化、排障与验证，覆盖容器/主机到端口 | 日常运维 |

> **Air 值得单独评估**：大规模集群的配置变更风险高，能在数字孪生上先跑一遍验证流程，对 RoCE 参数调优这类容易出事的操作尤其有价值。

## 5. 结合本集群的选型分析

### 5.1 与 H3C LS9867-128DH 的对标

| 维度 | NVIDIA SN5600 | H3C LS9867-128DH |
|------|---------------|------------------|
| 交换容量 | 51.2 Tb/s | 51.2 Tb/s |
| 端口形态 | **64× 800G** | **128× 400G** |
| 形态 | 2U | 2U |

**两者同档位**，当初的端口推导逻辑可直接互换。但在本集群“CX-8 的 800G 口拆成 2×400G”这一前提下：

- **128DH（128×400G）**：服务器侧 400G 直插，交换机侧**无需二次 breakout**，布线更简洁
- **SN5600（64×800G）**：交换机侧需再做一次拆分

这也是 128 口 400G 机型在本场景下更顺手的原因。

### 5.2 温度约束对比

| 设备 | 工作温度 |
|------|---------|
| SN5600 | 0–35 ºC |
| SN5400 | 0–40 ºC |
| **技嘉 G894-ZD3-AAX7（B300 节点）** | **10–30 ºC** |

**机房温控仍以服务器规格为准**（30ºC 上限），交换机侧有余量。

### 5.3 如果未来考虑 NVIDIA 方案

需要同时满足三点才能拿到 Spectrum-X 的完整收益：

1. 交换机用 Spectrum-4（SN5600）
2. 网卡用 BlueField-3 SuperNIC 或 ConnectX
3. 端到端按 Spectrum-X 参考架构配置

只换交换机、网卡保持现状，得到的是**标准 RoCEv2**，而非 Spectrum-X。
