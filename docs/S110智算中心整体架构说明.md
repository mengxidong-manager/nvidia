## 一、建设概况

S110 智算中心已建成并投入运行**两套 GPU 训练集群**，面向大模型训练与推理负载，在同一机房内通过共享存储骨干实现资源协同。

| 指标 | 规模 |
|------|------|
| **GPU 总数** | **1,272 颗** |
| GPU 计算节点 | 159 台 |
| 存储节点 | 130 台 |
| 网络交换机 | 123 台 |
| 设施总功率（含制冷） | 约 3.2 MW |

**两套集群构成**：

| 集群 | 节点 | GPU | 平台 | 计算网络 |
|------|------|------|------|---------|
| **H200 集群** | 32 台 | 256 颗 | Aivres KR6288 · HGX H200 | InfiniBand NDR |
| **B300 集群** | 127 台 | 1,016 颗 | 技嘉 G894-ZD3-AAX7 · HGX B300 | 双平面 RoCEv2 |

## 二、整体架构

![S110 智算中心整体网络架构](images/s110-overview-arch.svg)

架构自上而下分为三层：

**核心层** —— 两套集群各配置独立的冗余核心交换，H200 侧为 NVIDIA SN4600 × 2，B300 侧为 H3C S9825 × 2，承担南北向流量汇聚与对外互联。

**共享骨干层** —— 16 台 H3C S9825 组成的存储网 Spine，是两套集群唯一的交汇点。统一的存储骨干让 159 个计算节点共享同一套存储资源池，避免了按集群切分带来的容量碎片。

**集群层** —— 两套集群各自保有完整的计算网、存储接入与带外管理体系，在计算平面上完全独立，互不影响。

## 三、计算网络

计算网承载 GPU 之间的集合通信，是决定训练效率的核心环节。两套集群采用了各自适配的技术路线。

### 3.1 H200 集群：InfiniBand NDR

| 项 | 配置 |
|------|------|
| 设备 | NVIDIA MQM9790 × 24（8 Leaf + 16 Spine） |
| 单节点网卡 | 8 × 400G |
| 单节点互联带宽 | **3.2 Tbps** |
| 拓扑 | 轨道优化（rail-optimized）两层胖树 |

InfiniBand 在链路层天然无损，具备确定性低时延特性，适合对通信延迟敏感的训练任务。

### 3.2 B300 集群：双平面 RoCEv2

| 项 | 配置 |
|------|------|
| 设备 | H3C LS9867-128DH × 48（32 Leaf + 16 Spine） |
| 单节点网卡 | 8 × ConnectX-8 OSFP 800G |
| 单节点互联带宽 | **6.4 Tbps** |
| 节点内互联 | NVLink 1.8 TB/s |
| 拓扑 | 双平面轨道优化，**1:1 严格无阻塞** |

每个 800G 端口拆分为 2 × 400G，分别接入两个相互独立的通信平面。这一设计既充分利用了网卡带宽，又通过平面隔离提升了整体可靠性 —— 单一平面异常时，另一平面仍可维持通信。

交换机采用 128 端口 400G 机型，使网卡侧拆分出的 400G 链路可直接接入，无需在交换机侧二次转换，简化了布线结构。

### 3.3 轨道优化拓扑

两套集群的计算网均采用轨道优化设计：**每个节点的第 i 号 GPU 固定接入第 i 组交换机**。

这样，跨节点的集合通信（All-Reduce）在各自独立的轨道平面内完成，不同轨道之间互不争抢带宽，也无需经过上层交换。对于千卡规模的同步训练，这是保障扩展效率的关键结构。

## 四、存储架构

### 4.1 统一存储骨干

16 台 H3C S9825 构成的存储 Spine 同时服务两套集群，实现**存储资源池化**：

- 两套集群共用一套存储骨干，避免按集群切分造成的容量与带宽碎片
- 四列分布部署，横向扩展能力充足
- 存储节点与计算节点均采用双上行接入，链路级冗余

### 4.2 B300 集群存储能力

| 指标 | 数值 |
|------|------|
| 存储节点 | 64 台 |
| 单节点配置 | 24 × NVMe + 双 200G 光口 |
| 聚合带宽上限 | **25.6 Tbps ≈ 3.2 TB/s** |
| 裸容量 | 约 **23.6 PB** |
| 文件系统 | WEKA（启用 GPUDirect Storage） |

按业界参考标准，1,016 卡规模的训练负载所需存储带宽约 12.7 Tbps，当前配置提供**约 2 倍余量**，可从容应对 Checkpoint 写入等突发场景。

GPUDirect Storage 使数据从 NVMe 直达 GPU 显存，绕过 CPU 内存拷贝，显著降低数据加载环节的开销。

### 4.3 H200 集群存储

存储节点 66 台，通过独立的存储接入层汇聚至共享存储骨干。

## 五、管理与带外网络

全中心采用**三张网物理隔离**的设计：

| 网络 | 承载 | 隔离价值 |
|------|------|---------|
| **计算网** | GPU 集合通信（East-West） | 训练流量独占，不受其他业务干扰 |
| **存储网** | 数据读写、Checkpoint（North-South） | 大流量读写不冲击计算网 |
| **带外管理网** | BMC / IPMI | 与数据面完全隔离，异常时仍可远程操作 |

带外管理网保证了即使数据网络出现异常，运维人员仍可通过独立通道完成远程开关机、监控与系统部署，是大规模集群可运维性的基础保障。

## 六、调度与软件栈

集群采用**原生 Kubernetes** 作为统一调度底座，构建标准化的 AI 训练平台。

| 层次 | 组件 | 作用 |
|------|------|------|
| 底座 | kubeadm + containerd | 三节点控制面高可用 |
| GPU 管理 | NVIDIA GPU Operator | 驱动、设备插件、监控统一下发 |
| 高速网络 | NVIDIA Network Operator | RDMA / SR-IOV 接入，启用 GPUDirect RDMA |
| 调度 | KAI Scheduler | 整组调度、层级配额、拓扑感知 |
| 作业框架 | Kubeflow Trainer / MPI Operator | 分布式训练任务编排 |
| 可观测 | DCGM + Prometheus + Grafana | GPU 与网络全链路监控 |

**三项关键调度能力**：

1. **整组调度（Gang Scheduling）** —— 一个训练作业的全部 Pod 要么同时启动、要么都不启动，避免部分任务占用 GPU 却无法开工造成的资源闲置。
2. **层级配额** —— 支持按团队划分资源配额，并在空闲时允许超额使用，兼顾公平与利用率。
3. **拓扑感知调度** —— 作业优先调度至网络距离更近的节点组，减少跨层转发，提升通信效率。

## 七、供电与散热

| 项 | 配置 |
|------|------|
| 机柜密度 | 每柜 1 台 GPU 服务器 |
| 单柜功率 | 约 15.5 kW |
| 单节点供电 | 12 × 3000W 铛金电源，N+N 冗余 |
| 散热方式 | 风冷，冷热通道封闭 |
| IT 功率 | 约 2.2–2.4 MW |
| 含制冷总功率 | 约 3.2 MW |

采用一柜一台的部署密度，将单柜功率控制在标准高密风冷机柜的承受范围内，在满足散热要求的同时避免了液冷改造的设施投入。

## 九、架构特点

**资源池化** —— 统一存储骨干服务双集群，159 个计算节点共享同一套存储资源，提升整体利用率。

**严格无阻塞** —— B300 集群计算网实现 1:1 无收敛，千卡规模同步训练不受网络带宽制约。

**三网隔离** —— 计算、存储、带外管理三张网物理分离，故障域相互独立，可运维性强。

**平面冗余** —— 双平面设计使单一平面异常不致中断训练，提升大规模长周期任务的稳定性。

**统一调度** —— 原生 Kubernetes 配合整组调度与层级配额，支撑多团队、多任务的并发使用。
