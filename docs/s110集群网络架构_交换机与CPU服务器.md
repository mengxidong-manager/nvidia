# s110 集群网络架构 — 交换机与 CPU 服务器

> 承接 s110-b7 节点解析，把视角从单节点拉到整个 s110 场地：三张网的交换机分层，以及 GPU 节点之外的 CPU 服务器角色。
>
> 撰写人：孟希東

> **说明**：标注 **【实拍确认】** 为照片 / 标签可见信息；**【典型配置】** 为该级别集群的常见做法，具体型号请以现场为准。

---

## 0. 重要澄清：s110 是场地编号，同一场地内有两套独立集群

> ⚠️ **`s110` 是机房/场地编号（Site 110），不是单一集群的名字。** 同一场地内实际部署了两套 GPU 硬件完全不同、计算网完全独立的集群：

| 集群 | GPU 服务器 | 计算网协议 | 计算网 Leaf 交换机 |
|------|-----------|-----------|---------------------|
| **H200 集群** | Aivres KR6288（HGX H200，如 [s110-b7](HGX_H200训练节点网络结构_s110-b7.md)） | **InfiniBand NDR 400G** | NVIDIA **MQM9790-NS2F**（Quantum-2 液冷版）【实拍确认】，编号 `lbbz-leaf-1~6...` |
| **B300 集群** | Gigabyte HGX B300（详见 [Gigabyte_HGX_B300_服务器运维手册.md](Gigabyte_HGX_B300_服务器运维手册.md)） | **RoCEv2 以太网** | H3C Densivelo **S9827-128DH**【实拍确认】，编号 `roce-leaf-3/7/8/9/11/17/18/20/24/25/27/31/32...` |

**两套集群的计算网物理上完全隔离**（H200 走 IB 浅绿色 OM3 多模光纤 + `IBBZ`/`lbbz-leaf` 命名；B300 走 RoCE 黄色单模 DR4 光纤 + `roce-leaf` 命名），不要把两者的 leaf 交换机型号混用。

本文 §2.2/§3 记录的 **存储/CPU 网（H3C S9825 系列，leaf-3/leaf-4、mgt-leaf-1/2）** 服务器侧标签同样带 `s110` 前缀，目前判断这是**两套集群共用的场地级存储/CPU 网络基础设施**（同一场地内的 GPU 和 CPU/存储节点接入同一套存储网），但具体是否严格共用，或者两套集群各自也有独立的存储网分支，仍需现场进一步核实。

## 1. 网络分层总览

![s110 pod 拓扑](images/s110-pod-topology.svg)

延续节点侧的 8︰8︰2，场地内每套集群同样是三张物理隔离的网 + 带外，但两套集群的计算网彼此独立：

- **计算网**（集群专属，两套集群完全独立）：
  - H200 集群：InfiniBand NDR 400G，NVIDIA **MQM9790-NS2F**（Quantum-2 液冷版）【实拍确认】
  - B300 集群：RoCEv2 以太网，H3C S9827-128DH【实拍确认】（详见 [800G光模块与Leaf交换机连接方式详解.md](800G光模块与Leaf交换机连接方式详解.md)）
- **存储 / CPU 网（Ethernet）**：读写存储、CPU/管理节点接入、in-band 管理，目前判断为场地级共用设施。【实拍确认】由 H3C S9825 系列承载。
- **带外管理网（OOB）**：BMC/IPMI，1G 铜缆，独立平面。

## 3. 服务器如何接入存储/CPU 网

存储/CPU 网（leaf-3/leaf-4、mgt-leaf-1/2）承载两类不同角色的服务器接入，接入方式和目的不同：

### 3.1 GPU 服务器的存储网卡接入（ST-1/ST-2 口）

GPU 训练节点（H200 集群如 [s110-b7](HGX_H200训练节点网络结构_s110-b7.md)，或 B300 集群节点）除了各自集群专属的计算网卡，还各带 **2 条独立的存储网卡**上行到 leaf-3/leaf-4：

```
GPU 训练节点（H200 或 B300，具体归属待确认）
  ├── 计算网卡（H200: 8× IB rail → lbbz-leaf-N（MQM9790-NS2F）｜ B300: 8× RoCE rail → roce-leaf-N（S9827-128DH））
  ├── 1× ST-1 存储网卡 → leaf-3（如 J01）
  ├── 1× ST-2 存储网卡 → leaf-4（如 K01）
  └── 1× IPMI 带外网口 → mgmt-sw
```

- **用途**：读取训练数据集、写入 Checkpoint 到并行文件系统，属于"计算之外"的 I/O，与训练用的 AllReduce 通信完全隔离，避免数据 I/O 突发流量冲击低延迟的计算网
- **双网卡冗余**：ST-1/ST-2 分别接到不同物理 leaf（leaf-3/leaf-4），单台 leaf 故障时存储 I/O 降级但不中断
- **带宽**相对计算网低一档（存储访问模式是顺序/批量读写为主，不需要计算网级别的通信密度）

### 3.2 CPU/存储专用服务器的接入（非 GPU 节点，本次实拍确认更新）

场地内的纯 CPU 服务器不参与 GPU 计算、不接任何集群的计算网，只接存储/CPU 网 + 管理网。实拍确认了一台具体的 CPU/存储服务器背板与接线：

| 项 | 内容 |
|------|------|
| 服务器类型 | 通用 1U/2U 机架服务器（`Mgmt`/`FLEXIO 2`/`SLOT 4-6 HDD40-43` 命名风格，典型 Dell PowerEdge 或同类 OEM 设计） |
| 管理口 | `Mgmt`（BMC/iDRAC 专用口，独立于数据面） |
| 数据管理口 | `IOIOI`（板载 RJ45） |
| 本地调试 | VGA + 2×USB 3.0 |
| 存储/管理网卡 | FlexIO 插槽，2 个光模块，各接一根品红色 OM4 多模光纤 |
| 上联标签 1 | `osadrt-s110-c19u31-mgt-leaf-1-28-56` → **mgt-leaf-1**（机柜 C19，U31） |
| 上联标签 2 | `osadrt-s110-c20u31-mgt-leaf-2-28-56` → **mgt-leaf-2**（机柜 C20，U31） |

```
CPU/存储服务器
  ├── Mgmt 口（BMC/iDRAC）→ 独立带外管理
  ├── IOIOI 口 → 带内管理/数据
  ├── 网卡 1 → mgt-leaf-1（C19）
  └── 网卡 2 → mgt-leaf-2（C20）
```

- **双上联冗余**：与 GPU 服务器的 ST-1/ST-2 设计逻辑一致，两个网卡分别接到不同物理 leaf（mgt-leaf-1/mgt-leaf-2），单台 leaf 故障不中断服务
- **mgt-leaf 与 leaf-3/leaf-4 的关系**：命名不同但属同一逻辑层——存储/CPU 网并非只有一对 leaf，而是**按机柜分组分布式部署**多对 leaf，就近接入减少布线距离，最终汇聚到共同 Spine 层（详见下方分布式部署说明）

| 角色 | 作用 | 接入方式 |
|------|------|---------|
| 管理 / 头节点 | 集群管理（Base Command / BCM）、调度控制面（Slurm/K8s master）、PXE 装机 | 存储/CPU 网（就近 leaf 对双上联）+ 管理网 |
| 登录节点 | 用户 SSH、作业提交、代码编译 | 同上 |
| 存储节点 | 并行文件系统服务端（Lustre/GPFS/WEKA/Ceph）；大集群多为独立存储集群 | 存储/CPU 网（高带宽，可能多网卡绑定）+ 管理网 |

与 GPU 节点的关键区别：

- 不插计算网卡（无 rail 上联），只接存储/CPU 网的双上联口
- 网络需求集中在存储/前端与管理面，无需超低延迟计算网
- 数量少、功耗低，通常不需要 8× PSU 的重载供电

命名【实拍确认】：机柜/节点用 `s110-c19u31` / `s110-c20u31` 这类 `c<列>u<U位>` 格式；连接目标用 `mgt-leaf-N` 命名（区别于 GPU 侧的 `leaf-N`），提示这批 leaf 交换机专门服务管理/存储类服务器所在的机柜群。

### 3.2.1 存储/CPU 网的分布式 leaf 部署

实拍确认该层至少存在两组独立部署、物理位置不同的 leaf 对，各自就近服务不同机柜群：

| leaf 对 | 部署机柜 | 命名 | 主要服务对象 |
|---------|----------|------|--------------|
| leaf-3 / leaf-4 | J01 / K01 | `leaf-3`、`leaf-4` | 附近 GPU 训练机柜的 ST-1/ST-2 存储网卡（§3.1，集群归属待确认） |
| mgt-leaf-1 / mgt-leaf-2 | C19 / C20 | `mgt-leaf-1`、`mgt-leaf-2` | 附近 CPU/存储专用机柜的管理+存储网卡（§3.2） |

两组均为 H3C S9825 系列、品红色多模光纤、原生 RoCEv2，属于同一张逻辑网络（存储/CPU 网），只是物理上按机柜就近分布式部署——这是典型的大规模集群布线策略，避免远端机柜的存储流量长距离绕线，也便于按机柜群独立扩容和故障隔离。

### 3.3 两类服务器接入对比

| 维度 | GPU 训练节点（H200 或 B300） | CPU/存储专用服务器 |
|------|-------------|---------------------|
| 计算网 | H200: IB rail 全接 lbbz-leaf（MQM9790-NS2F）｜ B300: RoCE rail 全接 roce-leaf（S9827-128DH） | 不接 |
| 存储/CPU 网 | ST-1 + ST-2 双上联（接 leaf-3/leaf-4） | 双网卡上联（接 mgt-leaf-1/mgt-leaf-2，或其他就近 leaf 对） |
| 管理网 | 1 条 IPMI | 1 条独立 Mgmt(BMC) + 1 条 IOIOI 带内管理 |
| 供电 | 8× PSU 重载 | 通常 2× PSU 标准冗余 |

## 5. pod 命名规则汇总

| 片段 | 含义 |
|------|------|
| `s110` | **场地/机房编号（Site 110），非单一集群名**，场地内共存 H200 与 B300 两套独立集群 |
| `b*` | GPU 节点序号（H200 集群命名，如 b7） |

| `IBBZ` / `lbbz-leaf-N` | **H200 集群专属**：InfiniBand 计算网标识 / Leaf 编号（NVIDIA MQM9790-NS2F，如 lbbz-leaf-1~6...） |

| `spine-N-M` | 上联 Spine 层，N=spine 编号，M=端口 |

| `mgmt-sw` | 带外管理交换机（区别于 `mgt-leaf`，后者是存储/CPU 数据网 leaf，命名相近但层级不同，需留意区分） |
